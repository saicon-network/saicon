## 摘要

SAiCoN 是一条 Layer-1 区块链，其中验证者获得奖励是因为被度量的参与，而不是因为质押的规模。
每个纪元，协议都会为每一个验证者，依据它签署的区块与轮到它出块的次数计算一个参与度评分，
把该评分平滑为一个跌得快、恢复得慢的声誉值，并且只向那些活跃、合规且已积累参与的验证者付款。
质押保留两项作用——它让验证者获得准入，并为其奖励加权——但它不决定活跃集的成员资格，
那是由声誉决定的。集中度由针对验证者、针对运营它们的现实世界实体、以及针对整个网络的硬性限制
加以约束；合规、抗卡特尔与能源核算作为彼此独立的层强制执行，而不是被折叠进评分里。
原生代币 SCN 有一个 21,000,000 的固定上限，由唯一的发行模块在每次铸造之前强制校验，
而发行量则从一份安全预算推导而来，交易手续费会挤占它。该协议构建在 Cosmos SDK 与 CometBFT 之上，
运行在公开的开发者网络上，并由一整套已执行的仿真计划完成校准，本文报告其主要结果。

## 1. 引言

权益证明通过让作恶变得昂贵来保障网络安全：验证者押上资本，而当它发生等价物签名或消失时，
协议销毁其中一部分。这一设计已被证明是稳健的。它同时也带来一个结构性后果，
每一个成熟的权益证明网络都表现出这一点：共识权重与资本成正比，奖励与共识权重成正比，
而奖励又被再投资——于是质押的分布不断向最大的持有者漂移。典型的结果是这样一个验证者集合：
十个运营者控制着三分之一的投票权重，中本聪系数 [7] 停留在个位数，
而这个网络名义上拥有一百个验证者。

第二个后果更安静。在这样的网络上，**把验证者运行好**与**只是运行着**报酬相同。
在线率与诚实由惩罚来保障，而一个避开了惩罚的验证者，无论它是模范还是仅仅及格，
都能拿到与质押成比例的那一份。协议精确地度量资本，却只在边缘处度量参与。

SAiCoN 从一种不同的角色分配出发。**资本让验证者获得准入；参与决定它的影响力。**
验证者押上自质押并将其锁定，这确立了一个有真实风险敞口的真实运营者站在节点背后。
从那一刻起，它在网络中的地位由它所做的事计算而来——它签署的区块、轮到它出块的次数、
它一段时间内的行为——而活跃集正是依据这一地位来选举。质押继续为被选中的验证者所获奖励加权，
因此资本并未被忽视；它只是被限制在它确实能提供信息的那些角色里。

由此产生三项承诺，它们塑造了其余的设计。

**参与是被度量的，而不是被声称的。** 验证者的评分在共识中依据每个节点都能核验的数据计算：
区块头中的提交签名与出块者身份。评分中没有任何一部分依赖自我上报。

**每一项控制都住在自己的层里。** 合规是一道关卡：未通过的验证者被排除，无论它在别处发出什么信号。
去中心化是网络的性质，而不是任何参与者的性质，因此它以限制的形式强制执行，而不是被换算成分数。
能源核算在出现一个无法被收买的核验方之前，只具信息性。把其中任何一项折叠进参与度评分，
都会让验证者用在线率买通它们。

**参数来自实验。** 本文中的每一个数值参数，都由一次代码与输出均已公开的仿真选定或确认，
而校准一节说明了那些仿真度量了什么、又没有度量什么。

本文的结构如下。第 2 节概述 SAiCoN 所构建于其上的共识技术栈。第 3 节描述网络架构。
第 4 至 7 节规定验证者生命周期、参与机制、活跃集选举与质押限制。第 8 节规定发行与激励。
第 9 节涵盖罚没、合规、抗卡特尔以及协议的运行时不变式；第 10 节讲治理。第 11 节报告校准计划，
第 12 节讲实现现状，第 13 节讲相关工作。

## 2. 背景

SAiCoN 是一条以应用为中心的区块链，使用 Cosmos SDK [8] 构建于 CometBFT 共识引擎 [4, 9] 之上。
这一选择是刻意的，值得说明。

CometBFT——Tendermint Core 的继任者——提供带即时最终性的拜占庭容错共识：由超过三分之二投票权重
提交的区块即为最终，且协议会产出等价物签名的密码学证据，供应用层据此行动。Cosmos SDK 以一组可组合
模块的形式提供应用层——质押、罚没、分配、治理、银行、升级——它们已经保障了一大批生产网络。
跨链通信协议（IBC）[10] 则在共享这一技术栈的链之间提供最小化信任的转移。

SAiCoN 原封不动地保留共识引擎与标准模块。它的贡献是另外四个与之并列的应用模块，
以及在 SDK 把验证者集合交给共识引擎的那个边界上，用基于参与的选举取代按质押加权的选举。
这个位置很要紧：参与层不是对共识的修改——共识仍是一个被充分研究过的 BFT 协议——
而是一层应用级策略，决定哪些验证者进入共识、以及带多大权重进入。

技术栈的两个性质被直接用到。第一，每一个区块头都携带其出块者的身份与上一个区块的提交，
因此参与可以从已经属于共识一部分的数据计算出来，无需任何预言机。第二，SDK 在每个区块的开始与结束
处暴露了钩子，而 SAiCoN 的纪元推进、参与度记账与运行时不变式正是在那里执行。

## 3. 网络架构

### 3.1 共识与出块

区块由 CometBFT 以大约五秒的目标间隔产出。活跃集——即其签名计入三分之二门槛的那些验证者——
由第 6 节所述的协议选出，并在每轮轮换结束时作为一次验证者更新交给共识引擎。在一轮之内，
出块者由 CometBFT 自身的出块者选择机制决定，按投票权重加权。

协议中的时间以**纪元**度量，其定义为固定数量的区块。选择区块数而非挂钟时间是刻意的：
每个节点观察到的区块高度都相同，而时钟会漂移；以区块表达的参数在全网范围内是确定性的。

### 3.2 应用模块

四个模块实现了参与协议。此处先行列出，后续各节详加规定。

| 模块 | 职责 |
|---|---|
| 验证者注册表 | 验证者身份、状态机、准入、自质押锁定、退出 |
| 合规 | 合规标记、证据处理、监禁与受治理的恢复 |
| 参与 | 每个纪元的参与度评分、声誉平滑、作为奖励关卡的累加器 |
| 奖励 | 唯一的发行模块：发行、供应上限、手续费挤占、分配 |

另有两个模块补全整个设计：一个**质押引擎**，强制执行准入下限与第 7 节的质押限制；
以及一个**委托路由器**，负责放置委托并路由溢出。一个**实体注册表**记录每个验证者背后的实益所有人，
并强制执行实体层面的限制。

SDK 自带的通胀模块不在本应用中。第 8 节解释原因。

### 3.3 节点拓扑

SAiCoN 网络沿两条彼此独立的轴区分节点角色——节点*保留*什么，以及节点*暴露*什么。

| 角色 | 保留 | 暴露 |
|---|---|---|
| 验证者 | 共识状态与证据窗口 | 无——只连接到自己的哨兵 |
| 哨兵 | 每一个区块，状态经裁剪 | 点对点，面向互联网 |
| 全节点 | 每一个区块，状态经裁剪 | RPC 与 REST，带限流 |
| 归档节点 | 每一个区块与每一份历史状态 | 受限的查询访问 |

验证者从不直面公网。它在关闭对等交换的状态下运行，并且只与自己运营的哨兵保持常连接；
每个哨兵都把该验证者列为私有对等节点，因此它的地址从不被传播。位于不同地区、不同服务商的
两个哨兵是最低要求。应用流量——钱包、区块浏览器、索引器——由全节点与归档节点提供服务，
绝不由验证者提供。

### 3.4 公开接口

网络暴露标准的 Cosmos REST 与 RPC 接口——区块、交易、验证者、委托、供应量与质押参数——
并为每个 SAiCoN 模块提供查询端点：验证者注册表、按纪元的参与记录、按纪元的奖励记录与合规记录。
任何实现了 Cosmos 链建议流程的钱包都能无需修改地连接；SAiCoN 使用标准的 Cosmos 派生路径。
附录 C 列出了这些端点。

## 4. 验证者

### 4.1 状态

验证者始终且仅处于六种状态之一，而它们之间的转换被约束在一张固定的表内，
并由一条运行时不变式强制执行。

```
BONDING ──► ACTIVE ──► QUARANTINED ──► UNBONDING ──► INACTIVE
                └─────► JAILED ───────┘
```

| 状态 | 含义 |
|---|---|
| Bonding | 已注册；自质押锁定已开始；等待激活 |
| Active | 具备被选举资格；被选中时进行签名 |
| Quarantined | 因合规审查被隔离于共识之外，申诉通道开放 |
| Jailed | 因严重违规被排除 |
| Unbonding | 已请求退出；解绑周期正在进行 |
| Inactive | 已完全退出 |

### 4.2 准入

验证者凭其运营者**自身的质押**获得准入。自质押下限为 2,000 SCN。委托而来的质押永远不计入准入：
若计入，同一池代币就可以在许多候选节点之间以委托的形式反复使用，从而以一份质押的代价
为一整个组制造准入。自质押是运营者无法借给自己的资本。

自质押自注册起**锁定 60 天**。该锁定在交易受理处强制执行：运营者在窗口期内解绑或重新委托
自身质押的任何尝试，都会在执行之前被拒绝，包括经由授权许可转发的尝试。锁定下限是一个协议常量；
注册会拒绝更短的期限，且没有任何治理行动能够降低它。

### 4.3 退出

离开网络需要经过链 **21 天**的解绑周期。完成时刻在退出开始时即被固定，此后不可移动，
并且有一条运行时不变式禁止验证者在该周期走完之前变为 inactive。在锁定窗口之外对自质押做部分解绑，
只释放所声明的数额；其余部分继续参与。

### 4.4 监禁与恢复

双签由共识引擎的证据机制检测到。协议会自动回应：该验证者被罚没（第 9.1 节），
其合规标记被清除，状态转为 *Jailed*，而它的共识密钥会收到一个永久墓碑，
协议中没有任何消息能够移除它。从监禁中恢复是一项**治理行动**，须经过冷却期，
且合规解除绝不能绕过恢复关卡。

## 5. 参与

### 5.1 参与度评分

每个纪元结束时，每一个活跃的验证者都会得到一个 0–100 区间的原始评分：

```
PS = 0.50 · 在线率 + 0.35 · 出块质量 + 0.15 · 治理
```

*在线率*是该纪元中携带了该验证者签名进入提交的区块所占的比例。*出块质量*是该验证者实际承担的
出块轮次占其应得轮次的比例，其中应得轮次依据该验证者在投票权重中的份额逐块累积，
因此纪元之内集合发生的变化能被精确处理。*治理*是该验证者在一个回溯窗口内对链上投票的参与度，
其中没有任何提案开放的纪元记满分；它会在协议开始记录投票发生时刻之后进入评分，
在此之前其权重会在两个可度量的信号之间重新归一化。

参与度评分度量的是参与质量，别无其他。合规、卡特尔信号与能源核算都不是它的输入。

### 5.2 声誉

原始评分经由一个不对称滤波器被平滑为 **WARP**，即该验证者的声誉：

```
若 PS <  WARP :  WARP ← WARP − 0.65 · (WARP − PS)
若 PS ≥  WARP :  WARP ← WARP + 0.10 · (PS − WARP)
```

声誉以 0.65 的速率下跌，以 0.10 的速率回升。这份不对称是参与层的核心决策：
它让声誉易失而难得，从而使运营者的理性策略是持续参与，而不是周期性的最小努力式恢复。
新验证者从 80 的声誉起步。当声誉不低于 65 时，验证者**具备**被选举的资格。

这份不对称的代价是具体的。连续错过三个纪元的验证者，会从任何起始声誉跌到 5 以下，
此后需要十个纪元的完美参与才能重新越过资格门槛。

有两项策略保护评分，使其不去惩罚验证者并未造成的事情。**一次经确认的全网故障会冻结**每一个
验证者的声誉——两个方向都不更新——因为让所有验证者为一件谁都没有造成的事件受罚，
是协议绝不该产出的误报。而验证者遥测数据缺失的第一个纪元被当作证据缺席，而不是不利证据；
持续的沉默则记为零分，从而使沉默永远不会比上报更划算。

### 5.3 经验点与奖励关卡

在声誉之外，每个验证者还累积**经验点**：每个活跃纪元加一，并可选地向下限 1 衰减。
经验点是参与的长期记录，也是**奖励关卡**。协议只有在满足以下条件时才在某个纪元向验证者付款：

```
status = ACTIVE   ∧   合规   ∧   EP > 0
```

并且有一条运行时不变式断言：没有经验点的验证者一无所获。经验点只能通过参与模块的纪元计算发生
改变。一次处罚可以把验证者的声誉与当前进行中纪元的评分清零；它绝不能改动经验点或已关闭纪元的
记录，而合规模块面向参与模块的接口在结构上就够不到它们。

### 5.4 攻击

**选择性参与。** 一个只签署刚好足以保住资格的区块、其余一概漏掉以节省成本的运营者，
正是这个不对称滤波器在校准时所针对的画像。在选定参数下，被仿真的选择性画像在 0% 的纪元中被接纳，
而在对称滤波器下这一比例为 43.8%（第 11 节）。

**声誉囤积。** 运营者无法把声誉存起来再花掉：滤波器缓慢的恢复限制了盈余声誉的累积速率，
而快速的下跌会在一个缺席的纪元里把它花光。

**利用故障。** 一个验证者不会因为另一个验证者的失败而被压到门槛之下，因为评分只取决于它自己的
签名与轮次；它也无法利用全网故障，因为在这种情况下所有人的声誉都被冻结。

## 6. 活跃集选举

### 6.1 资格

当一个验证者处于活跃状态、合规，且声誉达到门槛时，它便具备被选举的资格：

```
候选池 = { v : status(v) = ACTIVE ∧ C(v) = 1 ∧ WARP(v) ≥ 65 }
```

实体上限（第 7.2 节）在选举**之前**施加于候选池。一次事后还需要修正的抽签算不上抽签。

### 6.2 活跃集

活跃集按 **75 个席位**设计，分两个阶段填满，每 **7 个纪元**重抽一次。集合规模是一个受治理的
质押参数——改动它既不需要重启也不需要迁移——最终取值由第 6.5 节的共识基准测试确定。
开发者网络的创世早于这项决定，因此仍沿用框架默认值，将通过一次普通的参数变更迁移过去。

**其中七成席位——75 席时为 53 席，60 席时为 42 席——是确定性的**，归属于声誉最高的合格验证者。
排序键只有声誉——不是投票权重，也不是质押量。理由是算术性的。在合格候选池之内，
声誉的跨度至多为 1.54 倍（从 65 到 100），而被接纳的质押跨度约为 8.7 倍
（从准入下限到单验证者上限）；一个把质押计入其中的排序，将是一个带着声誉色调的质押排序，
仿真也证实了这一点——一个乘性质押项复现纯质押排序的重合度达 98.6%（第 11 节）。

**余下的三成——75 席时为 22 席，60 席时为 18 席——是抽签席位**，从其余合格验证者中不放回地抽取，
票权随质量超线性增长，从而使抽签席位是挣来的而非白得的——并且**每个经核验的实体只有一张票**，
使运营者控制多少个身份都不改变其中签概率。

抽签的存在是为了让集合保持开放。一个纯确定性的排序会收敛到同一批运营者身上；
抽签让排名前列之外表现优良的验证者每一轮都有机会进入，也避免了长期席位的成本变成入场壁垒。

### 6.3 随机性

抽签由一个**可验证随机函数**[15] 播种，由验证者对该轮次的输入求值。其他方案经权衡后被否决：
基于区块哈希的随机性可被磨蹭操纵，因为某一高度的出块者事先已知，且掌握交易的打包权；
承诺—揭示方案无偏，但在预期候选人数下，每一轮次的开销约为两百笔交易。VRF 的输出是密钥与输入的
确定性函数，因此持有者无法为同一输入炮制出另一个结果，而且每个节点都能验证。
VRF 公钥在实体认证仪式中登记（第 9.3 节）。

### 6.4 投票权重

每个入选验证者的投票权重为

```
VP = min(bonded, validatorCap) × WARP / 100 × C
```

在集合内归一化后，作为其验证者更新写入共识引擎。投票权重同时对共识与奖励加权。其中没有任何
集中度项：集中度由第 7 节的上限处理，因此一个验证者的权重绝不会因为别人质押或解质押而变动。

### 6.5 集合规模

决策登记册 v1.0 定为 60 席，其选取依据是：在该点上，更大集合带来的去中心化收益被判定为超过
所测得的平均参与质量下滑。随后的复核轮次更倾向 **75**：它把最坏情况下前十名的投票权重份额从
约 38% 降到 34%，并把中本聪系数从约 9 提升到 10，代价是平均参与质量不足一个点；
而 90 席几乎买不到更多好处，却仍在继续拉低质量（第 11 节）。因此 75 是设计目标。
最终规模将由公共测试网上的一次共识基准测试确定——在 50、60、75 与 90 席下测量出块时间、
最终性、资源占用与流失恢复——在主网之前完成。

### 6.6 攻击

**以质押劫持排序。** 由构造排除：质押不是确定性排序的输入。

**磨蹭抽签。** 由 VRF 排除。

**身份拆分。** 一个把质押分散到多个验证者以收集抽签票或确定性席位的运营者，受实体上限约束：
无论运行多少节点，每个经核验的实体都只有两个席位与一张票。该上限依赖于弄清谁拥有什么，
这正是第 9.3 节的主题。

**隐蔽串谋。** 一组技术上健康、行动却如同一体的验证者，任何参与度评分都无法区分，
也没有哪个排序函数能解决它。防线是激活前的认证，以及第 9.3 节的检测阶梯。

## 7. 质押上限与委托

集中度由截断式的上限控制，而非由折扣式的惩罚控制。这个区别不是文风问题。惩罚只是压低集中的
边际回报，并不给它设界；上限则给它设界。上限在仿真中被度量过；没有任何一条惩罚曲线被度量过。

### 7.1 单验证者上限

任何验证者的有效质押不得超过**全网绑定质押总量的 2%**。基数每个纪元读取一次，并带有棘轮：
它在纪元之间可以自由上升，但每个纪元只能按一个受治理的百分比下降；因基数下降而被推到上限之上的
仓位会被冻结，而不是被强制削减。上限之上的质押仍然处于绑定与可罚没状态，但不产生投票权重、
不产生奖励，而指向已达上限验证者的新委托会被路由到别处。

### 7.2 实体上限

集中度控制的单位是**实体**——一个或多个验证者背后的现实世界运营者。每个经核验的实体：

- 其名下所有验证者的合计质押被限制在全网绑定质押总量的 **5%**；
- 其中至多 **2** 个验证者可占据活跃集席位；
- 它持有 **1** 张抽签票。

席位上限是关键杠杆。在仿真中，一个不受席位上限约束的建模攻击者达到了 53.8% 的投票权重，
并必然突破三分之一；而在每实体两席之下，其最大值为 3.2%，突破三分之一的概率为零。
把质押上限在 5% 与不设限之间变动，只让攻击者的权重在 3.2% 与 4.4% 之间移动。

### 7.3 全局绑定上限与排队

绑定质押总量被限制为**供应上限的 8% 与公开流通量的 60% 两者中的较小值**。达到上限后，
净新增质押进入**队列**；重委托以及对已退出验证者的替换仍然允许，因此上限约束的是总量，
而不冻结其构成。该上限为可同时锁入共识的代币份额设界，也就为暴露于罚没的经济体份额设界。

### 7.4 委托

委托人选择一个主验证者，并且至多可以分拆给 **3** 个。会把某个验证者推过其上限的委托将**溢出**，
溢出由委托路由器在仍有余量的合格验证者之间分配，按质量、预期活跃度以及当前质押量的倒数加权，
并排除处于监禁、隔离、低于声誉门槛或已达实体上限的验证者。该路由器在设计上是去中心化感知的：
它把溢出送离集中处，而不是送向收益最高的验证者。

被委托的质押与自绑定在同等条件下暴露于罚没。

### 7.5 攻击

**委托回收。** 受第 4.2 节的准入规则约束：委托不构成准入。

**大量小节点。** 受实体上限约束：无论一个实体运行多少节点，它都只有两个席位、一张票和 5% 的质押。

**质押冲击。** 一笔大额委托退出会拉低上限的基数；棘轮限制了每个纪元的下跌幅度并冻结超限仓位，
因此这次退出无法被用来迫使其他验证者在一个纪元内削减质押。

## 8. 发行与激励

### 8.1 SCN 代币

SAiCoN 的原生代币是 **SCN**。它是唯一的质押代币：验证者的自绑定与委托人的质押都以它计价，
奖励以它支付，交易手续费也以它收取。基本单位——`nscn`，即一亿分之一枚代币——以及八位小数精度
在测试网与主网上完全一致，本文中的每一个参数都原样沿用。

### 8.2 供应量与唯一的铸造路径

供应量上限为 **21,000,000 SCN**。这个上限是协议常量，不是参数，并且它作为每一次铸造的**前置条件**
被强制执行：发行模块先算出上限之下的余量，再把发行量夹到该余量之内，因此上限是阻止越界，
而不是事后发现越界。

有且仅有**一个模块能够铸造**。框架自带的通胀模块被完整地从应用中移除——不是通过配置禁用，
而是根本不存在——这样就不存在第二条持有创造供应权限的代码路径，并有一项接线测试断言确实没有。
纪元的奖励池**每个纪元只铸造一次**，不是每个验证者铸造一次，因此发行总量是一个被计算出来的量，
而不是一个循环累加出来的涌现结果。

一个由治理控制的发行断路开关可以停止发行，并对每一个本应获得付款的验证者记录原因。

### 8.3 安全预算

发行不是固定的通胀率。它每个纪元从一份**年度安全预算**——网络承诺付给验证者的金额——推导得出，
定义为

```
年度安全预算 = clip( 0.15 × 绑定总量,  0.005 × 供应量,  0.0075 × 供应量 )
```

也就是每年绑定质押量的百分之十五，下界为当前供应量的千分之五，上界为千分之七点五。
纪元的目标额是年度预算除以一年中的纪元数。按当前的网络快照，这大约相当于中位绑定水平下
每天 238 SCN、满参与度下每天 357 SCN，绑定质押的毛收益率约为 15%。
每天 1,100 的固定发行方案经评估后被否决：它意味着 46–70% 的收益率，并在九年之内耗尽上限。

### 8.4 交易手续费

交易手续费**顶替发行**。纪元的新增发行量等于安全预算目标额减去已经收到的手续费：

```
发行量   = max(0, 纪元目标额 − 手续费 − 结转余数)
奖励池   = 发行量 + 手续费
```

因此一个纪元永远支付其目标额，绝不多付。随着手续费收入增长，新的发行随之下降，
在年手续费约 10 万 SCN 时铸造完全停止，验证者仅由手续费获得报酬。
一个纪元分配后的取整余数以基本单位结转，并抵扣下一个纪元的发行量；它绝不会作为尘埃支付给任何一方。
分配满足守恒恒等式

```
铸造量 + 结转入 = 支付量 + 结转出
```

协议的测试直接断言这一点。

### 8.5 分配

奖励池在活跃集中通过第 5.3 节奖励关卡的验证者之间分配，每个验证者的份额与其投票权重成正比。
由于投票权重内嵌了声誉，这种分配是连续地奖励参与，而不是分档奖励：验证者的收入随其声誉、
随其受上限约束的质押而上升，没有任何阈值制造断崖。在单个验证者内部，奖励按有效质押的比例
在运营者的自绑定与其委托人之间划分，并扣除运营者的佣金。

### 8.6 佣金

运营者为其委托人的奖励设定一个佣金率，受协议最低值与一个受治理区间的约束，且变动速率有界。
最低值的存在是为了防止零费率的逐底竞争，那会让运营者无法覆盖运行节点的成本。
区间与默认值依据测试网数据校准（第 11 节）。

### 8.7 长期安全性

在手续费收入为零的情形下，供应上限大约在网络的第二十六年被触及，此后安全预算完全由手续费供给。
协议的手续费顶替规则正是为这一过渡而设计的：随着使用量增长，预算中由手续费支付的比例随之增长，
网络的安全支出便成为其经济活动的函数，而不是一笔逐渐枯竭的储备的函数。
触顶之后的供给规则——仅靠手续费、预先积累的储备，还是一个有界的终期发行——将在主网之前确定。

### 8.8 从 Base 上既有代币的过渡

项目社区目前在 Base 网络上持有一种更早的代币。在链自我验证期间，两套环境并行运行：Base 上的代币
仍是那里的经济代币，SCN 是链自身的单位，两者之间没有任何余额流动。当前建设的正是这一并行阶段，其间不存在迁移。

退出该阶段是一次经过批准的单一事件，而非渐进漂移。当链被判定已越过启动风险——即在外部安全审计、
公共测试网与主网创世之后——兑换为 SCN 的通道随即开启，Base 上代币的流通被关闭，Base 侧剩余的供应被销毁。
自此，SCN 成为唯一的代币，双代币阶段就此结束。

**兑换由为此预留的代币提供资金，绝不来自新增发行。** 这源于供应设计而非政策：上限是一个在每次
铸造前都会检查的常量，且全网只有一个模块能够铸造。若迁移以销毁的 Base 代币为凭据增发，那将构成第二条
发行路径，而本协议并不存在这样的路径。因此储备在创世时即已确定——先于它所资助的那次过渡，而不是
在过渡发生的当下。

由于过渡发生在审计之后而非之前，将要成为可罚没质押的余额，必然落在一个罚没机制已被独立评审过的
网络上。

## 9. 安全性

### 9.1 罚没

| 事件 | 后果 |
|---|---|
| 一般性掉线 | 不罚没任何质押。该验证者失去声誉、失去该纪元的奖励，并可能被监禁。一次经确认的全网故障对每一个验证者予以豁免。 |
| 双签 | 绑定质押的 **10%**——自绑定与委托按比例——清除合规标志、监禁，并在共识密钥上留下永久墓碑。 |
| 经证实的协同攻击 | 一条独立的、更重的、以证据为依据的规则，由治理依据公开证据裁定。 |

掉线被刻意排除在质押罚则之外。声誉已经承载了它的代价——一次故障需要十个纪元来恢复——
而针对掉线的质押罚则，会把一位遭遇硬件故障的诚实运营者，罚得和一位疏忽的运营者一模一样。

### 9.2 合规

每个验证者都带有一个**合规标志**，由合规模块维护，并由奖励关卡直接读取。针对某个验证者提交的证据，
或者一次双签，都会清除该标志；恢复清白须经由一套受治理的流程，绝不能由验证者自行完成。
该标志是二元的。合规是关卡，不是评分：若把它以任何权重放进参与度评分，
一个未通过它的验证者就能靠在线率把损失补回来，从而留在集合之内。

### 9.3 抗卡特尔与实体认证

第 7 节中每一条集中度上限都以实体为单位表述，而一条实体上限的效力，取决于协议对谁拥有什么的了解。
因此 SAiCoN 要求**在首次激活之前完成受益所有人认证**：一个验证者在能够被选举之前，
先与一个经核验的实体建立关联，其 VRF 公钥也在同一场仪式中登记。认证是第一道防线，
也正是实体上限得以真正可执行而非徒具其名的原因。

检测是第二道防线。一个由验证者之间行为相关性算出的风险评分驱动如下阶梯：

| 信号 | 动作 |
|---|---|
| 风险 ≥ 0.60 持续两个纪元 | 警告；仅作监控 |
| 风险 ≥ 0.75 持续两个纪元，且至少有两类相互独立的证据 | 隔离复核——72 小时之内启动，公布证据哈希，提供申诉途径，并承诺 14 天内完成复核 |

风险评分**本身绝不罚没**。隔离是在复核期间把验证者移出共识；它不触及质押，且可经申诉撤销。

检测的局限被直白地写出来，因为整个设计依赖于认清它。在仿真中，一组在保持技术健康的同时相互协调的
验证者，在十二周内约有九成的概率避开隔离。这正是认证先于激活、而非跟在检测之后的原因，
也是抗卡特尔设计建立在实体上限而非检测器之上的原因。

### 9.4 能源核算

SAiCoN 记录并公布验证者的能源来源。在当前设计中，它不为此附加任何经济后果——
没有关卡、没有投票权重调整、没有奖励乘数。理由来自度量。在六种候选政策中，
每一个为绿色认证付费的变体都制造出购买认证而非购买能源的激励——仿真中有 32.4% 的验证者暴露于
花钱换资格的风险；而每一个以此设卡的变体，在最不利的地区排除了 90.6% 无法取得认证的验证者。
纯信息性政策是唯一既无花钱换资格风险、又无地域伤害的政策。一项经济性试点——
限定为一个考虑豁免的百分之二调整——以存在一个误报率与漏报率均低于百分之二且具备地域覆盖的
核验方为前提条件。

### 9.5 运行时不变式

协议在每个区块结束时断言自身的一致性。这些断言不是记录日志——它们会**停住整条链**，
其原则是：一个账目已经悄然发散的网络，比一个已经停下的网络更糟糕。

| 不变式 | 陈述 |
|---|---|
| V-1 | 每个验证者持有一个合法状态，且每一次状态转移都在合法转移表内 |
| V-2 | 没有经验点的验证者得不到奖励 |
| V-3 | 在自绑定锁定期内没有自质押流出 |
| V-5 | 没有验证者在其解绑期届满之前变为非活跃 |
| V-7 | 参与记录只存在于活跃验证者 |
| V-8 | 经验点只通过参与发生改变；处罚绝不改动它们 |

在不变式之外，协议的测试还断言：不存在第二条铸造路径、每个纪元奖励池的精确守恒、
供应上限作为铸造前置条件、断路开关、锁定期对授权代发路由的抵抗，
以及每个模块状态的导出—导入往返一致。框架自带的标准仿真套件——完整应用、状态确定性、
导入/导出，以及导入后仿真——以固定随机种子对本应用运行。

## 10. 治理

SAiCoN 的治理是**有界的**。代币持有者通过框架的治理模块，就参数变更、升级以及被监禁验证者的
恢复进行投票。一次投票能够触及的范围，取决于每个参数的边界在何处被强制执行。

| 层级 | 含义 | 由谁强制 |
|---|---|---|
| 自由 | 治理可以设定该类型的任何取值 | 仅由类型本身 |
| 有界 | 治理可以在模块所编码的区间内设值 | 交付时校验：越界取值在提案执行时被拒绝，而不是在投票时 |
| 不可及 | 不是参数；属于代码变更 | 协议常量与运行时不变式 |

供应上限、唯一铸造路径、自绑定锁定期下限、运行时不变式以及墓碑都是不可及的：任何投票都动不了它们。
验证者注册表根本不带任何可治理参数。治理可以在边界之内调整参与度评分的权重、声誉滤波器、
纪元长度、上限百分比以及佣金区间，而每一次这样的变更都带有版本。它不得降低准入下限、
不得绕过或停用参与层、不得推翻一次罚没结果，也不得清除墓碑。参与协议无法被一次投票俘获。

## 11. 校准

本文中的每一个数值参数都由仿真选定或确认，而这些仿真连同其代码、输入与原始输出一并发布 [13, 14]。
此处的报告受两条规则约束。一次仿真只有真正执行过才算数。并且每一项结果都要连同它没有证明什么
一起陈述。

### 11.1 校准计划

一个七阶段计划选定了《参数决策登记册》[11] 中的参数：

**声誉动力学。** 在 384 组滤波器权重与门槛的组合中，44 组满足准入标准，其中一组是帕累托最优的：
下跌率 0.65、恢复率 0.10。相较对称的 0.8/0.2 滤波器，它把选择性参与画像的误接纳率从 43.8% 降到 0%，
把弱画像的误接纳率从 2.67% 降到 0%，并把声誉波动率从 0.359 降到 0.189，
代价是三日故障后的恢复变慢——十个纪元对三个纪元。

**活跃集与投票权重。** 在 300 种配置中，活跃集的平均声誉随集合规模单调下降——50 席时 94.2、
60 席时 93.4、75 席时 91.9、90 席时 90.2。当时选定六十，是作为质量与去中心化之间的折中；
复核轮次重新审视了它。一个质押乘声誉的投票权重模型把最坏情况下前十名的份额限制在 33.5%。

**委托与集中度。** 2% 的单验证者上限把前十名份额压在 22%，而 3% 时为 28%，
代价是对进入委托的接纳率下降。

**抗卡特尔。** 实体席位上限起了决定性作用，如第 7.2 节所述。

**发行。** 第 8.3 节的安全预算，以及对固定发行的否决。

**能源核算。** 在成本、资产锁定与核验误差等假设上比较了六种政策；
纯信息性政策是唯一既无花钱换资格、又无地域伤害的政策。

**综合压力测试。** 九个场景 × 五个随机种子 × 365 个纪元——合计 16,425 个被仿真的纪元。
六个场景通过；三个失败，而这些失败被转化为主网就绪标准，而不是被调参掩盖掉。
整个运行过程中的账目误差低于 3 × 10⁻⁸ 枚代币，奖励守恒误差低于 1.5 × 10⁻¹¹，供应上限从未被突破。

### 11.2 复核与后续研究

一个复核轮次重跑了计划中四个存有争议的部分，另有一组八项后续研究把它延伸到了将在主网迁移的池子的
真实脱敏分布——2,063 位持有人——以及原计划未曾隔离出来的一些问题。主要结果如下：

**集合规模。** 七十五优于六十：最坏世界下 P95 的前十名投票权重 38.3% → 34.2%，
P05 中本聪系数 9 → 10.2，平均技术质量 95.42 → 94.60；考虑实体的确认运行给出 32.3% 与 11。
九十在集中度上几乎不再带来改善，却仍在继续拉低质量。

**排序键。** 仅按声誉的确定性排序得到确认。指数为一的乘性质押项复现纯质押排序的重合度达 98.6%；
指数为二时为 94.4%。仅用声誉的排序把活跃集平均声誉保持在 87.8，而质押排序为 85.9，
前十名的投票权重份额则没有变化。

**准入。** 一个递增的准入阶梯——50 个验证者时 2,000，100 个时 2,500，200 个时 3,000，
300 个时 4,000——经评估未被采纳：其中两级超出了它自身对变动速率的限制，
而最后一级把小型运营者从可准入池中剔除了出去。最终保留了单一下限；它现为 2,000，
由该研究之后的决定设定，而非由该研究得出。

**真实分布下的单验证者上限。** 在一比一换算下，3% 是能在第一天基本接纳整个迁移池的最小上限；
5% 不带来更高的接纳率，反而使集中度变差。2% 上限在第一天造成的排队源自纪元起始时的分母，
在迁移后的基数下便消失了，这就把问题定位在接收规则上，而不在上限本身。

**治理信号不可度量时的声誉评分。** 在治理信号不可用的情况下，把它的权重在在线率与出块质量之间
重新归一化，在门槛 65 下仍会在 9.5% 的纪元中接纳选择性画像；而同一门槛下 50/50 的均等权重
一个纪元都不会接纳它，能在两个纪元之内检出为期七天的出块质量劣化，并且不增加任何恢复延迟。
让新验证者从资格门槛本身而非门槛之上起步，既保留了即时进入，又消除了弱画像本会享有的启动宽限。

**奖励分配。** 在一个固定池上比较了九种分配函数。创始纪元的奖励分档破坏了池的守恒，被否决。
一条有界的声誉梯度——同等质押下声誉 95 的验证者收入是声誉 75 者的 1.11 倍——
把前十名的奖励份额保持在 21.9%，委托人收益率的离散度维持在低位，每周付款方差低于百分之一。

**佣金。** 提出以百分之五作为下限，用以防范零费率竞赛，治理区间为 5–15%，默认值为 10%；
该研究没有找到延迟佣金更新生效的理由。

**迁移分布。** 基尼系数 0.799，赫芬达尔指数 0.0057，最大持有人占 2.9%，前十名合计 16.3%：
有集中，但不极端。二十九位持有人合计达到池子的三分之一。迁移首先撞上的限制是全局绑定上限，
而不是单验证者上限。

### 11.3 仍待度量的部分

每一项研究都是在真实或引用的余额之上使用合成的验证者行为。没有一项观测过生产网络。
在这些参数中的任何一个用于把关真实付款之前，声誉与评分参数都会在公共测试网至少九十天的真实纪元上
重新校准，其误排除率将由实测得出而非仿真得出；集合规模则由第 6.5 节的共识基准测试确定。

## 12. 实现状态

### 12.1 已在运行的部分

公共开发者网络运行着四个参与模块，以及两个让质押保持分散的模块——质押引擎（准入下限、单验证者上限与
全局上限，以及超出全局上限的质押所进入的排队）与委托路由器（一笔委托触及某个验证者的上限后，
继续流向仍有空间的其他验证者）。与之一同运行的还有完整的验证者生命周期——准入、锁定、退出、监禁与
受治理的恢复——参与关卡、带供应上限的唯一铸造路径、带手续费顶替与余数结转的安全预算发行、运行时
不变式，以及附录 C 中的公共浏览器、计分板与读取接口。参与度评分处于第一个版本，以在线率为其唯一
信号；投票权重目前仍按质押计算，基于参与度的选举是下一层。

### 12.2 主网就绪标准

主网——以及随之而来的真实奖励发放——将在以下标准全部关闭并经独立验证之后进行：

1. 一次确定活跃集规模的共识基准测试；
2. 在至少九十天真实纪元上对参与度参数的重新校准；
3. 每一个验证者在激活前完成受益所有人认证；
4. 在有基准真值的数据集上完成卡特尔检测器的校准，并配有申诉流程；
5. 一条质押冲击再平衡规则，使 30% 退出之后前十名份额保持在 35% 或以下；
6. 一份应急活性储备，在隔离与故障叠加时仍保持至少 90% 的席位被填满——75 席中的 68 席；
7. 一项运营成本与流动性评估，确认安全预算足以支撑真实运营；
8. 唯一铸造路径与供应上限通过集成测试——已完成；
9. 触顶之后的供给规则；
10. 能源核验方的经济学，若要启用经济性试点；
11. VRF 的实现——来源已选定，实现已排期；
12. 一份持续维护的、从《参数决策登记册》到代码的逐行映射——已完成。

以下取值在本文中是设计值，将在主网之前依据公共测试网的证据最终确定：活跃集规模（60 或 75）；
确定性席位与抽签席位之间的划分；抽签票权；奖励梯度；佣金下限与区间；全局上限的形式
（硬上限还是目标比率）以及流通供应量的链上定义；迁移接收规则；被罚没质押的去向；
以及触顶之后的供给规则。

## 13. 相关工作

**Cosmos Hub** [3] 按绑定质押量取前若干名作为活跃集，并按质押为共识与奖励加权。
SAiCoN 继承了它的共识引擎、模块框架与委托机制，而在选举这条边界上与之分道扬镳，
在那里它以参与度取代质押。

**Polkadot** [6] 通过一种意在把质押尽可能均匀地分布到当选集合中的选举方法，
从提名人的质押中选出验证者，从而通过选举而非上限来给集中度设界。
SAiCoN 通过显式的上限给它设界，并依据实测的参与度而非质押背书来选举。

**Ethereum** [2] 把每个验证者的质押固定为一个常数并随机抽取委员会，
这只有在运营者按每单位质押运行一个验证者的限度内，才使选举与其资本无关；
资本更多的运营者就运行更多验证者。SAiCoN 的实体上限在受益所有人这一层面处理同一个问题。

**Solana** [5] 在一套历史证明时钟之上按质押为出块人选举加权。它的贡献在于吞吐量；
它的选举是按质押加权的。

把声誉作为验证者选举的输入，在关于委托式共识与声誉式共识的文献中已有人提出。
SAiCoN 的具体贡献是：针对选择性参与对手校准出来的不对称声誉滤波器；
把合规、集中度与能源核算分离到评分之外、各成一层；把实体作为集中度控制的单位；
以及一条由构造而非由配置保证唯一的铸造路径。

---

## 14. 结论

SAiCoN 重新分配了权益证明赋予资本的那些角色。质押负责让验证者获得准入，并为其奖励加权；
实测的参与度决定它是否被选中、以及它的投票算多少分量。集中度由针对验证者、
针对其背后的实体以及针对整个网络的上限来设界；而那些评分无法诚实承载的控制项——
合规、抗卡特尔、能源核算——则各自作为独立的层来强制执行。代币有一个固定上限，
由唯一能够铸造的模块在每一次铸造之前强制检查，其发行则是一份随时间被交易手续费逐步顶替的安全预算。

该设计已在一个公共开发者网络上实现，由已执行的仿真加以校准，并按计划经由公共测试网与外部审计
走向主网。仍未确定的参数都被一一列名，并且每一个都将由测试网的证据、而不是由偏好来确定。

## 附录 B：记号与公式

| 符号 | 含义 |
|---|---|
| PS | 一个纪元的参与度评分，0–100 |
| WARP | 声誉，即被平滑后的参与度评分 |
| EP | 经验点，参与度累加器 |
| C | 合规标志，0 或 1 |
| VP | 投票权重 |

```
PS      = 0.50 · 在线率 + 0.35 · 出块质量 + 0.15 · 治理

在线率  = 已签署 / (已签署 + 已错过)                        在该纪元之内
出块质量 = min(1, 已出块数 / Σ_区块 power_i / totalPower)    逐块累积

WARP    ← WARP − 0.65 · (WARP − PS)      若 PS < WARP
WARP    ← WARP + 0.10 · (PS − WARP)      若 PS ≥ WARP
具备资格 ⇔ status = ACTIVE ∧ C = 1 ∧ WARP ≥ 65
获得付款 ⇔ status = ACTIVE ∧ C = 1 ∧ EP > 0

VP      = min(绑定量, 0.02 · 绑定总量) · WARP / 100 · C

年度安全预算 = clip(0.15 · 绑定总量, 0.005 · 供应量, 0.0075 · 供应量)
纪元目标额   = 年度安全预算 / 每年纪元数
发行量       = max(0, 纪元目标额 − 手续费 − 结转余数)
发行量       = min(发行量, 21,000,000 − 供应量)
奖励池       = 发行量 + 手续费
```
